# AutocompleteInput — Roadmap

---

## 🟠 Высокий приоритет

### `onSelect` callback

Сейчас при выборе подсказки компонент обновляет значение через нативный DOM-хак, а потребитель узнаёт об этом только через `onChange`. Нет способа отличить «пользователь напечатал» от «пользователь выбрал из списка».

```ts
onSelect?: (suggestion: T, inputValue: string) => void;
```

Нужно для: аналитики, side-эффектов при выборе (навигация, загрузка деталей), форм с дополнительной логикой.

---

### `minChars` — минимум символов для запроса

Сейчас эффект срабатывает при любом непустом значении. Если `getSuggestions` делает сетевой запрос, это неоптимально при вводе первого символа.

```ts
minChars?: number; // default: 1
```

Реализация: в `useDebouncedEffect` добавить проверку `restProps.value.length >= minChars`.

---

### Состояние ошибки

`getSuggestions` может упасть — сейчас ошибка только логируется, потребитель не знает о проблеме и не может показать UI.

```ts
onError?: (error: unknown) => void;
renderError?: () => ReactElement;
```

`renderError` отображается вместо списка подсказок. `onError` позволяет потребителю среагировать.

---

### Кэширование запросов

При возврате к ранее введённому значению компонент снова вызывает `getSuggestions`. Опциональный in-memory кэш устранил бы лишние запросы.

```ts
cacheResults?: boolean; // default: false
```

Реализация: `useRef<Map<string, T[]>>` с ключом по `value`. Инвалидировать при размонтировании.

---

## 🟡 Средний приоритет

### `emptyState` — рендер при пустом результате

Сейчас если `getSuggestions` вернул `[]`, dropdown просто не показывается. Потребитель не может показать «Ничего не найдено».

```ts
renderEmpty?: () => ReactElement;
```

Логика: показывать dropdown даже при пустом массиве, если `renderEmpty` задан и запрос уже был выполнен.

---

### `highlightMatch` — подсветка совпадения

Стандартное поведение autocomplete — выделять часть подсказки, которая совпадает с введённым значением. Сейчас текст подсказки рендерится as-is.

```ts
highlightMatch?: boolean; // default: false
```

Реализация: утилитарная функция, разбивающая строку на сегменты `[before, match, after]` и оборачивающая `match` в `<mark>`.

---

### Клавиша Escape

Сейчас Escape не обрабатывается — dropdown остаётся открытым. Нужно закрывать его и возвращать фокус на поле.

Реализация: в `onKeyDown` добавить `e.key === 'Escape' → dropdownRef.current?.closePopup()`.

---

### Controlled suggestions

Сейчас единственный способ подавать подсказки — через `getSuggestions` (async). Для локальной фильтрации (массив уже загружен) это избыточно.

```ts
suggestions?: T[]; // если задан — getSuggestions игнорируется
```

---

## 🟢 Низкий приоритет

### `debounceMs`

Задержка debounce зашита в коде как `300`. Стоит вынести в проп.

```ts
debounceMs?: number; // default: 300
```

---

### `maxSuggestions`

Ограничение числа отображаемых подсказок на стороне компонента, до передачи в `renderSuggestion`.

```ts
maxSuggestions?: number;
```

---

### `onLoadingChange`

Потребитель может захотеть реагировать на состояние загрузки — например, показывать индикатор снаружи компонента.

```ts
onLoadingChange?: (isLoading: boolean) => void;
```
